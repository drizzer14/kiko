# Table views and CSV export (1.4-tables) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or
> superpowers:executing-plans to implement this plan task by task. Steps use checkbox syntax.

**Status:** DRAFT. The spec waits for the user's rulings; no app code is written until they land.

**Goal:** Three exact monthly tables in Statistics (C1 categories, C2 cash flow, C3 net worth by
account) that share the charts' calculation, plus a CSV export of the user's own transactions.

**Architecture:** Task 1 moves the screen's spending composition into `src/statistics/spending-ledger`
and splits a per-holding core out of `buildNetWorthSeries`; each table is then a pure builder over
those. A design-system `DataTable` takes only strings and flags. D1 stands alone.

**Tech Stack:** React Native, TypeScript, Unistyles, drizzle `useLiveQuery`, react-native-fs, jest.

**Spec:** `docs/superpowers/specs/2026-11-03-tables-design.md` (written as if every recommended
ruling in its section 12 is taken; Decision 9 is planned as option A).

## Planner calls

- Task 7's `type` column composes the existing rule functions itself, by kind: it needs which rule
  matched, which task 1's union cannot say. It is a label, not a spending figure.
- `type` precedence: balance, loan, exchange, transfer, then the sign (expense or income).
- CSV values `type`, `source`, `pending` follow the app language, as the headers do.
- CSV rows run oldest first, by time and then id; matching reads every holding, writing only rows of
  non-archived accounts. `category` is the resolved title, as the charts fold it; empty for `balance`.
- CSV reads through `readDataSnapshot`, one-shot on Share, not a live query.
- `toFileShareUrl` becomes an export of the `share-anchor` module, not a copy (see wrong citations).
- The hook keeps one memo per old screen memo with the same inputs: an account toggle must not rerun
  the ledger-wide matchers. The pure builder composes the same part functions.
- D7 lands as the last commit of task 1, so a "no" drops exactly that commit.
- Columns start at the month of `spanStart` when the period reaches back further: no leading empty
  months. The account filter does not move columns; it moves only the first complete month.
- Period: `SelectField` in the filter bar slot, for its long labels (tabs-vs-chips rule); the designer
  may switch to the bar's own button after the device look. Spec section 13 leaves this to the builder.
- The view and the period live in the store of `use-statistics-filter-selection`;
  `resetStatisticsFilterSelection` resets them too, or suites leak state into each other.
- Table mode's category menu takes its options from the period's slices, not the date range's: a pure
  `buildCategoryOptions` moves out of the `categoryOptions` memo in task 3.
- C1 rows: largest period total first, as the donut, with the "All" row last. A month with no spend
  shows `0`. C3 rows skip an account with no holding.
- C3 row order is `filtered.filteredAccounts`; task 5 step 1 pins it against the Accounts screen.
- Percent shows whole in the cell and with one decimal in the VoiceOver value.
- `formatMoney` gains an optional third argument for digits and no symbol; a rounded zero has no sign.
- Task 6: a `BottomSheet`, not a pushed screen: no route params, and `sheetGeneration` already closes
  it when the screen stops showing. Month and Total cells open; Average, net, rate and C3 cells do not.
- Task 6 gets the payment of a loan row from a helper beside the id builder in `loan-payments`; the
  entry shape does not change.
- The privacy markdown is re-dated in task 7's commit and again at publish, per release skill
  "Privacy policy check" ("Never edit the markdown without bumping its effective date").
