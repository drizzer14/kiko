# Table views and CSV export (1.4-tables) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or
> superpowers:executing-plans to implement this plan task by task. Steps use checkbox syntax.

**Status:** user rulings landed 2026-11-03 (spec section 12). The "**Rulings:**" lines below state what is ruled.

**Goal:** Three exact monthly tables on an own Tables screen, opened from Statistics (C1 categories, C2 cash flow,
C3 net worth by account), that share the charts' calculation, plus a CSV export of the user's own transactions.

and splits a per-holding core out of `buildNetWorthSeries`; each table is then a pure builder over
those. A design-system `DataTable` takes only strings and flags. D1 stands alone.

**Spec:** `docs/superpowers/specs/2026-11-03-tables-design.md` (rulings in its section 12).

## Planner calls

- Task 7's `type` column composes the existing rule functions itself, by kind: it needs which rule
  matched, which task 1's union cannot say. It is a label, not a spending figure.
- `type` precedence: balance, loan, exchange, transfer, then the sign (expense or income).
- CSV values `type`, `source`, `pending` follow the app language, as the headers do.
- CSV rows run oldest first, by time and then id; matching reads every holding, writing only rows of
  non-archived accounts. `category` is the resolved title, as the charts fold it; empty for `balance`.
- CSV reads through `readDataSnapshot`, one-shot on Share, not a live query.
- `toFileShareUrl` becomes an export of the `share-anchor` module, not a copy (see wrong citations).
- The hook keeps one memo per old screen memo with the same inputs: an account toggle must not rerun
  the ledger-wide matchers. The pure builder composes the same part functions. Hook and builder both
  call one union function, `excludedIdsOf(parts)`, whose `ExclusionParts` type requires every set, so
  a new set cannot land in one of them only.
- D7 lands as the last code commit of task 1, so a "no" drops exactly that commit.
- Columns start at the month of `spanStart` when the period reaches back further: no leading empty
  months. The account filter does not move columns; it moves only the first complete month.
- Period: `SelectField` on the Tables screen, for its long labels (tabs-vs-chips rule); the designer
  may change it after the device look. Spec section 13 leaves this to the builder.
- The view and the period are route params of the Tables route, through `setParams` (spec section 5),
  so a fold or a resize keeps them and a new push opens on the defaults. The accounts and categories
  stay in the store of `use-statistics-filter-selection`, unchanged.
- The Tables category menu takes its options from the period's slices, not the date range's: a pure
  `buildCategoryOptions` moves out of the `categoryOptions` memo in task 1. S keeps its manual trend
  keys by passing them as `keptKeys`; Tables passes only its held picks.
- C1 rows: largest period total first, as the donut, with the "All" row last. A month with no spend
  shows `0`. C3 rows skip an account with no holding.
- C3 row order is `filtered.filteredAccounts` (`buildFilterScope`, task 1); task 5 step 1 pins it
  against the Accounts screen.
- Percent shows whole in the cell and with one decimal in the VoiceOver value.
- `formatMoney` gains an optional third argument for digits and no symbol; a rounded zero has no sign.
- Task 6: a `BottomSheet`, not a pushed screen: no route params, and `sheetGeneration` already closes
  it when the screen stops showing. Month and Total cells open; Average, net, rate and C3 cells do not.
- Task 6 gets the payment of a loan row from a helper beside the id builder in `loan-payments`; the
  entry shape does not change.
- The privacy markdown is re-dated in task 7's commit and again at publish, per release skill
  "Privacy policy check" ("Never edit the markdown without bumping its effective date").

## Review Focus

1. A transfer whose legs fall in two months: both stay out, since exclusion reads the whole ledger.
   Owner: task 3 step 1, task 4 step 2.
2. A device that changes time zone, and a DST month: month edges are local and whole. Owner: task 1
   step 1. (Users are displaced worldwide; memory `kiko-users-ukrainian-globally-displaced`.)
3. A language or base currency switch while a table shows: titles, headers and amounts follow at once.
   Owner: task 3 step 5.
4. A held category or account pick: a category pick never changes C2 or C3; a pick of a since archived
   account reads as "all"; no rows in the period shows an empty state, never a grid of zeros. Owner:
   task 3 step 5, task 4 step 5, task 5 step 4.
5. The app dies with the share sheet open: the plain-text file goes at the next launch, with or
   without a screen open; a fold during a share deletes nothing early; text with a delimiter, quote or
   newline stays one cell. Owner: task 7 steps 1, 3 and 4.
6. A balance-set row beside a real row of the same amount: it never pairs with it, takes its partner or takes its funding
   match, in the charts, the tables and the funding caption alike. Owner: task 4 step 1.
